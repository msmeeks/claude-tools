About this walkthrough

Every feature release deserves a demo, but making one is slow: record the screen, edit the video, write the narration, burn the subtitles, create the HTML script. demo-gen does all of that in one command, using AI models that run entirely on your machine.

1

The problem: demo creation is a tax on shipping

Without demo-gen, a typical feature demo takes:

  • ⏱ Screen recording: 15 min
  • ✂️ Video editing: 30 min
  • 🎙 Voiceover recording & sync: 20 min
  • 📝 HTML script: 30 min
  • Total: ~95 minutes per feature

With demo-gen:

  • ⚡ One command: ~2 min (standard) or ~30 sec (draft)
  • 🏠 Fully local: no cloud services, no subscriptions
  • 🎨 Per-project branding via design tokens
  • 📦 HTML + MP4 + SRT in one output directory
demo-gen doesn't eliminate judgment — you still choose what to demo and what screenshots to use. It eliminates the mechanical work of turning that judgment into polished artifacts.
2

Install demo-gen and dependencies

# 1. Install ffmpeg (required for video assembly)
$ brew install ffmpeg

# 2. Install demo-gen
$ pip install demo-gen
Successfully installed demo-gen-0.1.0

# 3. Install Ollama for local LLM scripting
$ ollama pull llama3.2
pulling manifest... done

# 4. Download TTS models (~90MB)
$ demo-gen download-models --tts-only
✓ kokoro/kokoro-v1_1.onnx
After this one-time setup, every future demo run is fully offline. Model weights are verified by SHA-256 checksum on every load.

Run your first demo — one command

Understand the six-stage pipeline

1 ScriptOllama/Claude
→
2 AssetsPillow / MoviePy
→
3 VoiceKokoro ONNX
→
4 SlidesPillow
→
5 Videoffmpeg
→
6 HTMLJinja2

All intermediate files live in a temporary directory that is deleted automatically on completion — including on error. The only files written to disk are the final outputs in your --output-dir.

Every stage is skippable via --format html (skips stages 3–5) or --format mp4 (skips stage 6). Use --format html in CI for maximum speed.
5

Add real screenshots to upgrade from placeholder mocks

# Pass screenshots in the order they should appear in the demo
$ demo-gen generate \
  --product "My App" \
  --feature "Dashboard" \
  --screenshot screenshots/empty-state.png \
  --screenshot screenshots/populated-dashboard.png \
  --screenshot screenshots/export-modal.png \
  --polish standard \
  --format both \
  --output-dir ./output
demo-gen validates all screenshot paths before running: checks the file exists, verifies the extension is in the allowed list (.png, .jpg, .jpeg, .webp), and rejects paths starting with - to prevent argument injection.
6

Apply custom branding with tokens and brand voice

# Create your token file (only override what you need)
$ cat acme-tokens.json
{ "brand_gradient_start": "#4c1d95", "brand_gradient_end": "#6366f1", ... }

# Pass both files to demo-gen
$ demo-gen generate \
  --product "Acme Platform" \
  --feature "Reports" \
  --tokens ./acme-tokens.json \
  --brand-voice ./BRAND_VOICE.md \
  --format both \
  --output-dir ./output
Design tokens propagate to every visual element: header gradient, step circles, caption borders, takeaways card, and video slide backgrounds. See the branding demo for a side-by-side comparison.
7

Use production polish for customer-facing releases

$ demo-gen generate \
  --product "My App" \
  --feature "Reports" \
  --screenshot screenshots/s1.png \
  --screenshot screenshots/s2.png \
  --tokens ./my-tokens.json \
  --brand-voice ./BRAND_VOICE.md \
  --polish production \
  --voice am_adam \
  --tone professional \
  --format both \
  --output-dir ./help-docs/demos/features/
--polish production adds: red highlight rings + callout labels on screenshots, gradient takeaways section, IntersectionObserver sidebar nav, best Kokoro voice, C5+E5 chord SFX, and fade+slide transitions. Use it for anything a customer will see.
8

Use the /demo skill in Claude Code to generate automatically

# In a Claude Code session, after shipping a feature:
/demo reports

# Claude Code detects demo-gen in PATH and runs:
demo-gen generate \
  --feature reports \
  --brand-voice ./BRAND_VOICE.md \
  --polish standard \
  --format both \
  --output-dir help-docs/demos/features/
The /demo skill in Claude Code automatically delegates to demo-gen when it's installed. No configuration needed — just ensure demo-gen is in your PATH. Falls back to ffmpeg/drawtext generation if not installed.

Key Takeaways

  • demo-gen replaces ~95 minutes of manual demo work with one command
  • All processing runs locally by default — no cloud services, no data leaving your machine
  • The six-stage pipeline produces HTML, MP4, and SRT in a single run
  • Design tokens and BRAND_VOICE.md make every demo match your product's identity
  • Three polish levels cover every workflow from CI preview to customer release
  • The /demo Claude Code skill auto-delegates to demo-gen when installed
