Installation

demo-gen requires Python 3.9+ and ffmpeg.

1. Install ffmpeg

# macOS
brew install ffmpeg

# Ubuntu / Debian
sudo apt-get install ffmpeg

2. Install demo-gen

pip install demo-gen

Or from source:

git clone https://github.com/your-org/demo-generator
cd demo-generator
pip install -e ".[dev]"

3. Install a local LLM (recommended)

demo-gen uses Ollama for local script generation by default. Install it, then pull a model:

ollama pull llama3.2
You can skip Ollama if you use --cloud mode with an Anthropic API key — but local is preferred for privacy.

4. Download TTS models

demo-gen download-models --tts-only

This downloads Kokoro ONNX voice weights (~90MB) to ~/.demo-gen/models/. SHA-256 verified automatically.

First demo

Generate a standard-polish demo in two lines:

demo-gen generate \
  --product "My App" \
  --feature "User Onboarding" \
  --polish standard \
  --format both \
  --output-dir ./output

demo-gen will:

  1. Ask Ollama to write a structured demo script for "User Onboarding"
  2. Synthesize a voiceover using Kokoro TTS
  3. Compose step slides as PNG images with Pillow
  4. Assemble slides + audio into an MP4 with ffmpeg
  5. Render a self-contained HTML demo script

Output in ./output/:

output/
  user-onboarding.html   ← demo script (open in browser)
  user-onboarding.mp4    ← video with voiceover and subtitles
  user-onboarding.srt    ← subtitle file

Add screenshots

Pass real screenshots and demo-gen will embed them in both the HTML and the video:

demo-gen generate \
  --product "My App" \
  --feature "Dashboard" \
  --screenshot screenshots/step1.png \
  --screenshot screenshots/step2.png \
  --screenshot screenshots/step3.png \
  --polish production \
  --format both \
  --output-dir ./output

With --polish production, demo-gen adds a red highlight annotation ring around the key UI element in each screenshot. To tell it where to draw the ring, pass a callout_region in a custom script — or let it place the ring automatically based on the LLM's judgment.

Screen recordings

You can also pass a screen recording and demo-gen will extract a still frame at the 1-second mark:

demo-gen generate \
  --product "My App" \
  --feature "Task Flow" \
  --recording recording.mp4 \
  --format both \
  --output-dir ./output

Branding & tokens

demo-gen uses a design token file to control all colors in generated HTML and video slides. Pass your own token file to match your product's brand:

demo-gen generate \
  --product "Acme Platform" \
  --feature "Reports" \
  --tokens ./acme-tokens.json \
  --brand-voice ./BRAND_VOICE.md \
  --format both \
  --output-dir ./output

Token file format (design_tokens.json)

{
  "brand_gradient_start": "#0f172a",
  "brand_gradient_end": "#6366f1",
  "brand_primary": "#6366f1",
  "brand_primary_light": "#e0e7ff",
  "brand_primary_dark": "#3730a3",
  "highlight_color": "#f59e0b",
  "highlight_shadow": "rgba(245,158,11,0.12)",
  "page_bg": "#f8fafc",
  "card_bg": "#ffffff",
  "body_text": "#0f172a",
  "secondary_text": "#475569",
  "app_shell_sidebar_bg": "#0f172a",
  "caption_border_width": "4px",
  "tagline": "Your product tagline here."
}
Only provide the keys you want to override. Any missing keys fall back to demo-gen's defaults.

Brand voice file (BRAND_VOICE.md)

Create a BRAND_VOICE.md in your project root and pass it with --brand-voice. demo-gen reads it before writing any script and matches your voice, tone, and terminology. See the branding demo for an example.

Local vs cloud

demo-gen is local-first. By default, all processing runs on your machine — the script, the audio, the video assembly. Nothing leaves your network.

Local mode (default)

demo-gen generate --product "My App" --feature "Login" --local

Uses Ollama for script generation. Requires Ollama running locally with your chosen model pulled.

Cloud mode

export ANTHROPIC_API_KEY=sk-ant-...
demo-gen generate --product "My App" --feature "Login" --cloud

Uses the Claude API for script generation. Before sending, demo-gen shows a pre-flight prompt listing every file it will transmit and asks for confirmation.

Screenshots are never sent to the API in cloud mode — only the text context files you explicitly list with --include-docs.

Privacy

See PRIVACY.md for the full data flow description. The short version: use --local if your screenshots contain production user data.

Manage models

# Check what's downloaded
demo-gen list-models

# Download TTS models only
demo-gen download-models --tts-only

# Download all models
demo-gen download-models

# Re-download (e.g. to verify integrity)
demo-gen download-models --force

Models are stored at ~/.demo-gen/models/. SHA-256 checksums are verified against a pinned manifest on every download and on every load.

Claude Code integration

If demo-gen is installed in your PATH, the /demo Claude Code skill automatically delegates to it:

/demo feature-name

This runs:

demo-gen generate \
  --feature feature-name \
  --brand-voice ./BRAND_VOICE.md \
  --polish standard \
  --format both \
  --output-dir help-docs/demos/

If demo-gen is not installed, the skill falls back to its built-in ffmpeg/drawtext approach.

FAQ

I get "model not found" when running demo-gen.

Run ollama pull llama3.2 first, or pass --local-model <model-name> to match whatever model you have. Use ollama list to see installed models.

The voiceover is silent / there's no audio in the MP4.

Run demo-gen download-models --tts-only to fetch the Kokoro ONNX weights. For --polish draft, demo-gen uses Piper or produces a silence track — install piper-tts for draft audio.

Can I use demo-gen with a custom ffmpeg path?

Yes. Set the environment variable FFMPEG_BINARY=/path/to/ffmpeg before running. Alternatively, ensure your custom ffmpeg is first in $PATH.

Does demo-gen work offline after setup?

Yes, completely. Once Ollama models and TTS weights are downloaded, no network access is required. All processing is local.

Can I run demo-gen in CI?

Yes. Use --polish draft for speed. Set ANTHROPIC_API_KEY and pass --cloud if you want Claude for scripting in CI (be mindful of what files you pass with --include-docs). The pre-flight consent prompt is skipped in non-interactive environments.

My design tokens are being ignored.

Verify the token file is valid JSON with an object at the top level. Run cat your-tokens.json | python3 -m json.tool to check. All required keys must be present (see token schema reference).
