# Brand Voice — demo-gen

## Product

**Name:** demo-gen
**Tagline:** "Ship demos as fast as you ship code."

## Voice attributes

Precise, practical, fast, approachable.

## Audience

Software engineers and developer-experience teams who need polished demo artifacts without a video production team. They value speed and automation over ceremony.

## Writing rules

- Active voice, present tense.
- Lead with the outcome, not the mechanism.
- Keep CLI output concise — one line per status update.
- Error messages: state what went wrong and the exact flag to fix it.
- No marketing fluff in CLI output.
- Docs and help text: sentence case, plain English, no jargon.

## Demo tone

- **Pace**: Measured — one action per beat, ~150 wpm narration.
- **Opening**: State the user problem, then show the solution.
- **Narration style**: First-person plural — "We start by…", "You'll see…"
- **Closing**: Reinforce the key benefit. End with the product tagline.

## Visual personality

- Neutral, token-driven colors by default (deep blue gradient, white cards).
- Per-project branding via `design_tokens.json` overrides.
- Clean, minimal — demo content is the hero, not chrome.
